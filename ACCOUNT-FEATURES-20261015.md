# Account and support update

- A first deposit without a referrer (blank or the zero address) displays a warning and requires explicit acknowledgement in the transaction review. The transaction client rechecks registration before requesting any transfer or approval. Existing registrations do not need to repeat this warning; referral relationships are unchanged.
- The highlighted deposit allocation box is removed from the entry form. Transaction review and the contract transparency/terms disclosures retain routing details. Contract cash routing and fees are unchanged.
- Referral Level 1/2/3 totals show historical USD volume generated at that exact referral depth, including deposits, reinvestments and settled sales. The reader subtracts successive subtree totals after verifying complete propagation, at a single block. Deeper descendants are excluded. Withdrawals do not erase historical volume. Readers are bounded to 4,096 jobs/edges; larger histories require a persistent server index. Pending propagation, inconsistent snapshots and oversized histories show an explicit unavailable state, never a fabricated total. Totals load on request, not with every account poll.
- Automatic reward-line calculation scans all available independent direct branches at one block, applies the deployed first-stage branch cap, excludes already assigned branches, and proposes strong branches first. This is a deterministic suggestion for a new group's first stage, not an optimizer for all future groups. Larger assignments are reviewed in batches of 64. It does not reassign existing groups or send transactions automatically.
- Support tickets are persisted in `/var/lib/globaldroptrade-api/community.json`. Wallet message signatures authenticate one-time five-minute challenges; bearer sessions last one hour and stay in browser memory. Tickets are private to their author and the current contract owner. Owners can reply, and users can close/reopen their tickets. Public announcements are readable without a wallet; only the current contract owner may publish or unpublish. No seed phrase, private key or blockchain transaction is required for support authentication. This does not send email or Telegram messages.
- The data file uses serialized atomic writes with restrictive permissions and survives API release changes. Back it up outside the release directory. Do not run multiple API writers against the same JSON file.

## Install on the existing reviewed BNB Testnet host

`bash ubuntu-community.sh` installs the frontend plus the unprivileged systemd API. It preserves the existing TLS configuration instead of invoking Certbot again, preserves the API environment, and refuses a different existing chain or contract. It requires at least 2 GiB free space. Empty API RPC/contract values are populated explicitly for chain 97 and the existing `0x7f19354B765920B9b17003d0840EEaA133883DcA` deployment. No mainnet or new smart-contract deployment is performed. Support administrator access is the live contract owner's wallet, not automatically the wallet of the person running the installer.

Validation: 39 frontend tests, including real local-contract referrer/level checks; 9 community and settlement API tests; mocked unprivileged API install/update/rollback check; TypeScript and production build; shell syntax checks. Live installation and real wallet flows remain to be verified after the user runs the installer.
