# Global testnet host move to 185.114.206.44

This release prepares a separate Ubuntu 22.04 or 24.04 server, transfers the
existing Global application privately, and supports continuation of the
previously authorized fresh testnet deployment. It does not change contract
economics or deploy to mainnet. Dravon and all source project directories and
backups are retained.

## Host preparation

On the **new host**, check out this exact reviewed release under
`/opt/globaldroptrade-host-bootstrap`, then run:

```bash
bash ubuntu-new-host.sh --prepare --target-ip 185.114.206.44
```

The script refuses the known old hostname, a non-local destination IP, an
unsupported OS, and preexisting Global application paths. It installs OS
dependencies and creates a private destination marker. It does not activate
Global services or create blockchain transactions. Existing Dravon files are
never selected. The target architecture must match the source; the transfer
preflight checks this before copying the source Node runtime.

Preparation requires at least 4 GiB free. Transfer performs a separate capacity
check for both the import and restored copy plus 1 GiB of working space.

## Private transfer

On the **old host**, run the verified `scripts/host-transfer.py` from this
release, using the target SSH port (22 by default):

```bash
python3 scripts/host-transfer.py --execute --target 185.114.206.44 --port 22
```

SSH host-key verification and authentication happen in the user's terminal.
Do not put a server password, wallet key or RPC token into a command, chat,
repository or public file. The helper logs rsync diagnostics privately and
streams files directly to the destination; no large archive is created on the
cramped source disk.

The initial copy leaves the source online. A read-only destination check must
verify the transferred runtime, chain 97, contract code and consistent target
identity before the final synchronization. If the private RPC restricts source
IPs, allow the new server address in that provider first.

Before the final copy the helper disables only Global timers, waits for the
running failover and financial workers to finish naturally, obtains financial
locks, refuses pending signed journals, and stops the Global support API. It
never kills a signing worker or stops Dravon. The final checksum pass and
private file hashes must succeed before the snapshot is marked consistent.

Expect `HOST_TRANSFER_COPIED_SOURCE_GLOBAL_FROZEN`. Source Global services stay
disabled, including after a reboot. This is intentional: local filesystem locks
cannot serialize two independent signing hosts. Keep the source and destination
private migration state until the entire move has been verified.

The selected data includes private configuration and keys, all Global financial
journals/policies/reset sessions, support tickets and announcements, managed
releases and runtime, website, backups, fallback signer state, reset checkout,
Global service definitions, scoped Nginx configuration and its certificate
lineage. It does not copy all of `/root`, all of Nginx, or Dravon's service state.

## Restore and continue the fresh testnet installation

On the **new host**, from this release checkout, run:

```bash
bash ubuntu-new-host.sh --finish-testnet --target-ip 185.114.206.44
```

Use a systemd transient oneshot with `TimeoutStartSec=infinity` and `UMask=0077`
for this final command so closing the terminal cannot terminate deployment.
The restore requires a consistent, fenced snapshot; checks hashes, architecture,
safe paths and read-only RPC identity; restores original paths; adjusts only the
support API's state ownership; and starts only the API after Nginx validation.
It leaves financial services disabled until the separate reviewed reset starts.

The reset preserves its old-generation archive and resumes saved deployment
transactions instead of clearing journals. It creates the already requested
empty testnet generation, connects the site, applies the existing hourly
position policy and previously authorized test-only reward top-up. Completion
requires `RESET_COMPLETE` with the actual new address. `HOST_RESTORE_COMPLETE`
alone confirms only restoration of the previous connected generation.

An unexpected old contract address, an incomplete transaction, a mismatched RPC
receipt or historical data failure still blocks the reset. A new server does
not establish RPC correctness or prove recurring live payouts.

## Domain and rollback

Point the existing domain and `www` to `185.114.206.44`. Remove or update a stale
IPv6 record if it routes clients to another host. The copied certificate is
verified locally with the requested hostname; verify public HTTPS and renewal
after DNS propagation. Keep deposits paused during fresh-generation replacement:
cached old frontend pages can still contain the previous contract address.

On failure retain both hosts and all journals. Never restart the old financial
worker merely because the new command failed. If the destination has signed,
first fence it, inspect receipts and transfer its latest progress back before
resuming the source. The source transfer session records prior service states
privately for reviewed recovery. Do not use the legacy `ubuntu-domain.sh` or
`ubuntu-community.sh` unchanged on the new host: their historical IP and vault
settings are fixed.

## Verification limits

Local tests verify guards, scope, freeze ordering, snapshot integrity and resume
behavior with isolated fixtures. No live transfer, DNS change, server
installation or blockchain transaction is asserted by this release. The
operator must run the commands on the specified hosts and inspect their actual
completion output.
