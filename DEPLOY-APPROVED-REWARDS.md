# Approval-enabled testnet deployment

Run `bash ubuntu-deploy-approved.sh --execute` from this reviewed checkout on the existing GlobalDropTrade server as root. This sends a testnet deployment transaction using the existing deployer file at `/etc/globaldroptrade/migration-deployer.key` or `/root/global-testnet-v071/.testnet-server/deployer.key`. Keys remain on the server. Node 22.12+ and the existing `/etc/globaldroptrade/trades.env` are required.

The source is pinned to chain 97, `0x731Ba0644e8f44BbBd48124F945724ba534431eb`, and its verified runtime hash. The new owner is `0x5bC282A45A8a1d7D9b915f04fC1D4031156d7632`. The separate deployer must be `0xf2ad0FB5288785E58943070De6CF6A1f7a68FBB2`. No mainnet deployment is supported. Fees are bounded to a cumulative 0.1 test BNB by the retained transaction journal.

This path loads the reviewed `artifacts/DeferredRewardsVault.json` and pins its creation-bytecode hash. It does not use the legacy deployment-console artifact or the old fresh-deployment journal. Source ownership and runtime identity are rechecked before signing or broadcasting. A signed transaction is persisted before broadcast. Repeating the command resumes the same hash and cannot silently deploy a second candidate. Changing the source, owner, signer or artifact requires review instead of reusing the journal.

Successful output includes `APPROVAL_CONTRACT_DEPLOYED_AND_VERIFIED`, `NEW_CONTRACT`, `WITHDRAWAL_QUEUE`, `TX_HASH` and `OWNER`. Verification checks three confirmations, the canonical block, configured owner, constructor settings, empty account ledgers, the queue's fixed vault address and `APPROVAL_VERSION()==1`. The private report is `/var/lib/globaldroptrade/approved-rewards-v1/deployment-public.json`. Keep its journal to resume after an interrupted connection.

The deployed candidate starts empty and uses the reviewed plan defaults. Existing users, positions, groups, balances, settings changed by governance and pending withdrawals are not imported. The source is not paused or modified, funds are not moved, and website/API configuration is not switched. The report explicitly records `accountsMigrated:false`, `siteConnected:false` and `cutoverAllowed:false`. A separately reviewed transition for the currently active deferred source is required before connection; the legacy `TestnetMigratedRewardsVault` constructor rejects this source. Daily automation additionally needs reporter authorization, a funded reward budget and its local signing key.

Preparing and testing this deployment workflow does not constitute a public-chain deployment. Only a successful server execution and verified receipt establish the new contract address.

Validation: all 10 tests in `test/approved-deployment.test.mjs` and `test/testnet-migration.test.mjs` passed on a local chain with ID 97. They cover legacy pending-request preservation, reviewed artifact identity, wrong-chain and wrong-owner rejection, source identity rechecks, a lost broadcast response and idempotent resume. Shell and JavaScript syntax checks passed. Public RPC access from the preparation environment timed out; public-chain signing and server execution were not performed here.
